# 07. Потоковый ввод-вывод и манипуляторы

← [C++ — оглавление](<./C++ — оглавление.md>)

```cpp
#include <iostream>   // cin, cout
#include <iomanip>    // манипуляторы с параметрами
using namespace std;
```

## Вывод: `cout`

`cout` — console out, `<<` — оператор вставки. Можно цепочкой:

```cpp
cout << "Значение суммы: " << sum << "\n";
cout << "Значение суммы: " << a + b << "\n";   // и выражения тоже
```

## Ввод: `cin`

`cin` — console in, `>>` — оператор извлечения.

```cpp
cin >> a >> b;
```

- значения разделяются пробелами/переводами строк, ввод завершается Enter
- дробная часть — через **точку**
- старое значение переменной затирается

```cpp
double a, b;
cout << "Введите два числа: ";
cin >> a >> b;
cout << "Сумма чисел равна: " << a + b << "\n";
```

> [!tip] Приглашение перед вводом
> Всегда выводи `cout << "Введите ..."` перед `cin` — кроме задач на Stepik, где вывод сверяется посимвольно и лишний текст ломает проверку.

### Как `cin` разбирает ввод

`>>` пропускает все пробельные символы слева, читает столько символов, сколько подходит под тип, и **останавливается** на первом неподходящем — оставляя его в буфере.

```cpp
int a; char c;
cin >> a >> c;      // ввод: 42x
                    // a == 42, c == 'x' — читалось из одной «строки» без пробелов
```

### Состояние потока — почему программа «зависает» или врёт

Если введённое не подходит под тип, поток переходит в состояние **fail**: переменная получает `0`, мусорные символы **остаются в буфере**, и все последующие `cin >>` молча ничего не делают.

```cpp
int n;
cin >> n;              // пользователь ввёл "abc"
cout << n;             // 0, и дальше весь ввод сломан
```

Проверка и восстановление:

```cpp
if (!(cin >> n)) {              // сам cin приводится к bool
    cin.clear();                // сбросить флаг ошибки
    cin.ignore(10000, '\n');    // выбросить мусор из буфера до конца строки
}
```

`while (cin >> x) { ... }` — идиоматичное «читать до конца ввода»: цикл завершится по EOF или по неверным данным. На Stepik это стандартный способ прочитать неизвестное заранее количество чисел.

> [!warning] Смешивание `>>` и `getline`
> `cin >> n` оставляет `\n` в буфере, и следующий `getline(cin, s)` прочитает пустую строку. Лечится тем же `cin.ignore()`. Подробнее — на теме строк.

## Манипуляторы

| Манипулятор | Действие |
|---|---|
| `endl` | перевод строки (+ сброс буфера) |
| `dec` / `hex` / `oct` | система счисления при вводе и выводе |
| `setbase(n)` | база 8, 10 или 16 (только вывод) |
| `setw(w)` | ширина поля для **следующего** вывода |
| `setprecision(p)` | число цифр после точки |
| `setfill(ch)` | символ-заполнитель (по умолчанию пробел) |
| `fixed` | фиксированная точка |
| `scientific` | плавающая точка (научный формат) |

> [!warning] `setw` действует однократно
> `setw` сбрасывается после первого же вывода. Все остальные (`setfill`, `setprecision`, `fixed`, `hex`) — «липкие», действуют до следующей смены.

> [!note] `endl` vs `"\n"`
> `endl` дополнительно сбрасывает буфер вывода. В циклах это заметно тормозит — там лучше `"\n"`.

### Системы счисления

```cpp
int a, b, sum;
cin >> oct >> a;      // ввод в восьмеричной
cin >> hex >> b;      // ввод в шестнадцатеричной
sum = a + b;
cout << dec << sum << endl;          // 54
cout << setbase(8) << sum << endl;   // 66   (или << oct <<)
```

Проверка: `32₈ = 26₁₀`, `1C₁₆ = 28₁₀`, сумма `54₁₀ = 66₈`. ✔

Если параметр `setbase()` не 8/10/16 — сброс на десятичную. **Двоичного манипулятора в стандарте нет** (в C++20 появился `std::format` с `{:b}`).

### Ширина и заполнение

```cpp
cout << "Сумма = " << setw(7) << setfill('$') << sum << endl;
// Сумма = $$$12.5
```

Если число не влезает в заданную ширину — выводится целиком, ширина игнорируется.

### Точность

```cpp
cout << "Сумма = " << fixed << setprecision(2) << sum << endl;
```

- знаков больше → округление
- знаков меньше → дополняется нулями
- **без** `fixed` `setprecision` задаёт число **значащих** цифр, а не знаков после точки
