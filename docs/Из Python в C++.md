# Из Python в C++

← [C++ — оглавление](<./C++ — оглавление.md>)

Не часть курса — про то, где привычки из Python дают неверный результат.

## Что меняется в голове

| | Python | C++ |
|---|---|---|
| типизация | динамическая, тип у значения | статическая, тип у переменной, известен на компиляции |
| размер числа | `int` неограничен | фиксированное число байт → **переполнение** |
| переполнение | не бывает | тихо, для знаковых — UB |
| исполнение | интерпретация | компиляция в машинный код |
| ошибка типа | во время выполнения | на компиляции (это подарок, а не помеха) |
| область видимости | функция | **любой блок `{ }`** → [05 Область действия и видимости](<./05 Область действия и видимости.md>) |
| память | GC | твоя забота (пока не дошли до указателей) |

## Одинаково выглядит — работает по-разному

```python
7 / 2      # 3.5
-7 % 2     # 1
7 // 2     # 3
2 ** 10    # 1024
a, b = b, a
```

```cpp
7 / 2          // 3      целые → целое
7.0 / 2        // 3.5
-7 % 2         // -1     знак делимого, не делителя
pow(2, 10)     // нет оператора **
swap(a, b);
```

→ подробности в [08 Операции и выражения](<./08 Операции и выражения.md>)

## Синтаксис

| Python | C++ |
|---|---|
| отступы | `{ }`, отступы не значат ничего |
| нет `;` | `;` после каждого оператора |
| `#` | `//` и `/* */` |
| `and or not` | `&&  \|\|  !` (хотя `and`/`or`/`not` тоже валидны — их не используют) |
| `elif` | `else if` |
| `True/False/None` | `true/false/nullptr` |
| `print(x)` | `cout << x << "\n"` |
| `input()` | `cin >> x` |
| `f"{x:.2f}"` | `fixed << setprecision(2) << x` |
| `len(s)` | `s.size()` |
| `list` | `std::vector` |
| `dict` | `std::map` / `std::unordered_map` |
| `str` | `std::string` |

## Чего в Python просто нет

- **объявление до использования**: переменная должна быть описана раньше, чем встретится
- **заголовочные файлы и `#include`** — препроцессор буквально вставляет текст файла
- **неявные преобразования типов** с потерей данных, о которых никто не предупредит → [10 Преобразование типов](<./10 Преобразование типов.md>)
- **UB (undefined behavior)** — программа может работать «правильно» и упасть при смене компилятора
- **этап сборки**: компиляция → линковка. Ошибка линковки ≠ ошибка компиляции

## Привычки, которые стоит взять сразу

1. Инициализируй фигурными скобками: `int x{0};` → [11 Списковая инициализация](<./11 Списковая инициализация.md>)
2. Собирай с `-Wall -Wextra` — компилятор расскажет про половину багов
3. `double`, а не `float`
4. `static_cast<T>(x)`, а не `(T)x`
5. Никогда не сравнивай вещественные через `==`
