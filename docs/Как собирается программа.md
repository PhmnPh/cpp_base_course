# Как собирается программа

← [C++ — оглавление](<./C++ — оглавление.md>)

Курс этого не объясняет, но без понимания этапов не разобрать половину ошибок. В Python исходник просто запускается; в C++ между текстом и запуском четыре шага.

```
исходник.cpp
    │  ① препроцессор     (#include, #define, вырезание комментариев)
    ▼
трансляционная единица (один большой .cpp-текст)
    │  ② компилятор       (проверка синтаксиса и типов)
    ▼
объектный файл .o        (машинный код, но с «дырами» на месте чужих функций)
    │  ③ компоновщик      (linker: подставляет адреса, подшивает библиотеки)
    ▼
исполняемый файл         ./a.out
    │  ④ запуск
    ▼
результат
```

## Три вида ошибок — и как их различить

| Этап | Как выглядит | Пример причины |
|---|---|---|
| **компиляция** | `error: ... expected ';'`, указана строка | опечатка, необъявленная переменная, несовпадение типов |
| **компоновка** | `Undefined symbols`, строка **не** указана | функция объявлена, но не определена; не подключена библиотека |
| **выполнение** | падение, `Segmentation fault`, неверный ответ | деление на 0, выход за границы, логическая ошибка |

> [!danger] Реальный случай — `clang` вместо `clang++`
> ```
> Undefined symbols for architecture arm64:
>   "std::__1::cout", referenced from: _main
> ld: symbol(s) not found
> ```
> Это **ошибка компоновки**: код скомпилировался, но `clang` не линкует стандартную библиотеку C++ (`libc++`). Компилировать надо `clang++`. Признак этого класса ошибок: в сообщении фигурирует `ld` и нет номера строки.

## Команды

```bash
clang++ -std=c++17 -Wall -Wextra -g task.cpp -o task && ./task
```

| Флаг | Зачем |
|---|---|
| `-std=c++17` | версия стандарта (иначе может взяться старая) |
| `-Wall -Wextra` | предупреждения — **включай всегда** |
| `-g` | отладочная информация для отладчика |
| `-o имя` | имя выходного файла |
| `-O2` | оптимизация (для замеров скорости) |

Посмотреть, что выдал препроцессор:

```bash
clang++ -E task.cpp | less
```

## CMake

В проекте `~/Projects/stepik/cpp_base_course` сборкой рулит CMake — он сам вызывает компилятор для каждой цели.

```cmake
cmake_minimum_required(VERSION 3.20)
project(cpp_base_course)
set(CMAKE_CXX_STANDARD 17)

add_executable(l02_task07 lesson2/task7.cpp)   # одна строка = одна программа
```

Новый файл задачи → дописать `add_executable` и переконфигурировать. Диалог «добавить файл в существующий target», который предлагает расширение CMake Tools, можно закрывать `Esc`.

```bash
cmake -S . -B build && cmake --build build
```
