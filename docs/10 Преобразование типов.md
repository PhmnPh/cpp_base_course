# 10. Преобразование типов

← [C++ — оглавление](<./C++ — оглавление.md>)

Если операнды операции разных типов — они приводятся к одному. Преобразование бывает **неявным** (компилятор сам) и **явным** (задаёт программист).

## Неявное расширяющее

В выражении (справа от `=`) короткие типы приводятся к длинным. `bool`, `char`, `short` всегда сначала → `int` (integral promotion).

При этом `true` → `1`, `false` → `0`, а `char` → его код.

Иерархия:

```
(bool, char, short) → int → unsigned int → long → unsigned long
                    → float → double → long double
```

```cpp
int  a = 8;
long b = 56;
long c = a + b;        // int + long → long + long

float  x = 7.8;
double y = x + 3.14;   // float + double → double + double
```

## Неявное сужающее — опасное

В **присваивании** правая часть приводится к типу левой, возможно с потерей данных. **Компилятор об ошибке не сообщает.**

```cpp
int a = 3.14 * 2;   // double(6.28) → int, a == 6
```

```cpp
int q = -5;
unsigned int h;
h = q;              // h == 4294967291 — знак потерян, число искажено
```

> [!danger] Ответственность на программисте
> Потеря и искажение данных при сужении — не ошибка компиляции. Защита есть: списковая инициализация → [11 Списковая инициализация](<./11 Списковая инициализация.md>).

## Порядок важен

Преобразование выполняется перед **каждой** операцией, поэтому зависит от порядка вычислений.

```cpp
int   a;
float b;
float c = 3.5;

b = a = c;    // присваивание правоассоциативно: b = (a = c)
              // a = c  → сужение, a == 3
              // b = a  → b == 3 (!)
```

А если бы `b` и `c` присваивались напрямую (`a = b = c`, где `b`, `c` — `float`), то `b == 3.5`, `a == 3`.

## Явное преобразование

### C-style (устаревший)

```cpp
(тип) выражение
```

```cpp
int a = 1;
double z = (double)a / 2;      // 0.5

float x = 25;
// int y = x % 4;              // ошибка: % только для целых
int y = (int)x % 4;            // ок
```

### C++-style

Четыре операции: `static_cast`, `dynamic_cast`, `const_cast`, `reinterpret_cast`. Синтаксис: тип в **угловых** скобках, выражение в **круглых**.

| Оператор | Когда |
|---|---|
| `static_cast<T>(x)` | обычные преобразования — **это тебе и нужно** |
| `dynamic_cast<T>(x)` | во время выполнения, по иерархии наследования |
| `const_cast<T>(x)` | снять `const` — избегать |
| `reinterpret_cast<T>(x)` | побитовая переинтерпретация — избегать |

```cpp
int a = 1;
double z = static_cast<double>(a) / 2;   // 0.5

float x = 25;
int y = static_cast<int>(x) % 4;

int i = 90;
// i = i / 3.7;                          // предупреждение о потере данных
i = static_cast<int>(i / 3.7);           // предупреждения нет
```

> [!tip] Почему `static_cast` лучше C-style
> Компилятор проверяет корректность на этапе компиляции, преобразование заметно в тексте (легко грепается), и оно не может «случайно» сделать то, что делает `reinterpret_cast`. Разница станет очевидна на теме указателей.
